\begin{frame}
  \frametitle{Spectral Ops}

  \begin{center}
    Spectral ops are about \emph{data flow}.
  \end{center}
    
  \medskip
  
  Two categories:
  \begin{itemize}
  \item One-way
    \begin{itemize}
      \item $
    \text{input}
    \rightarrow \text{read op}
    \rightarrow \mathcal{F}
    \rightarrow \text{write op}
    \rightarrow \text{output}
    $
    \item examples: shift, window, filter, scale
    \end{itemize}

  \item round-trip\\
    \begin{itemize}
    \item$
      \text{input}
      \rightarrow \text{read op}
      \rightarrow \mathcal{F}
      \rightarrow \text{mid op}
      \rightarrow \mathcal{F}^{-1}
      \rightarrow \text{write op}
      \rightarrow \text{output}
      $
      \item examples: Poisson solve, convolution, correlation
    \end{itemize}
  \end{itemize}

\end{frame}

\begin{frame}
  \frametitle{Spectral Ops: ops}

  \medskip
  Operations are:
  \begin{itemize}
  \item local (scalar)
  \item can have many inputs
  \item can have many outputs
  \item depend on index and batch number
  \item have user-supplied constants
  \item quadratic mid-ops may require dealiasing (ie conv)
  \end{itemize}

  \medskip

  There are lots of possible operations and combinations thereof.

  \medskip

  You know, maybe we need to specify an array of ops at each stage,
  each op associated with certain inputs/outputs.  For example, with
  GESTS, they probably have different differential operator for the
  passive scalar field than for the velocity field, and the scalar
  field is simulated with lower resolution.  But they both need to end
  up at the same mid-op length.
  

\end{frame}
