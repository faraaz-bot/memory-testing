\begin{frame}
  \frametitle{Spectral Ops}

  \begin{center}
    Spectral ops are about \emph{data flow}.
  \end{center}
    
  \medskip
  
  Two categories:
  \begin{itemize}
  \item One-way
    \begin{itemize}
      \item $
    \text{input}
    \rightarrow \text{read op}
    \rightarrow \mathcal{F}
    \rightarrow \text{write op}
    \rightarrow \text{output}
    $
  \item examples: shift, window, filter, scale
    \end{itemize}

  \item round-trip\\
    \begin{itemize}
    \item$
      \text{input}
      \rightarrow \text{read op}
      \rightarrow \mathcal{F}
      \rightarrow \text{mid op}
      \rightarrow \mathcal{F}^{-1}
      \rightarrow \text{write op}
      \rightarrow \text{output}
      $
      \item examples: Poisson solve, convolution, correlation
    \end{itemize}
  \end{itemize}

\end{frame}


\begin{frame}
  \frametitle{Spectral Ops: One-way Examples}

  \begin{itemize}
  \item Window filter
    \begin{itemize}
    \item Input: real 1D array.
    \item Read-op: $f_{i_x} \rightarrow H(i_x) f_{i_x}$
    \item $H$ is a Hamming window, Hann windows, Blackman windows, \dots
    \item Use case: DSP
    \end{itemize}

  \item Phase-shift-and-scale
    \begin{itemize}
    \item Input: multiple 1D complex arrays of length $N$
    \item Each 1D array is shifted by phase $\theta(b)$ and scaled by $\lambda(b)$
    \item Read op: $X_{i_x,b} \rightarrow \omega_N^{i_x \theta(b)} \lambda(b)X_{i_x,b}$
    \item Use case: radio astronomy.
    \end{itemize}
  %% \item $y$ derivative of a 2D Hermitian array
  %%   \begin{itemize}
  %%   \item Read op: $X_{i_x, i_Y,b} \rightarrow \frac{2 \pi}{L_y} i_y  X_{i_x,b}$
  %%   \end{itemize}
  \item $x$ derivative of a 2D Hermitian array
    \begin{itemize}
    \item Define $$k_x= \frac{2 \pi}{L_x}\begin{cases}i_x &\text{ if } i_x < N_x / 2\\ N_x -i_x &\text{otherwise}\end{cases} $$
    \item Read op: $X_{i_x, i_Y,b} \rightarrow i k_x  X_{i_x,b}$
    \end{itemize}
  \end{itemize}
  
\end{frame}

\begin{frame}
  \frametitle{Spectral Ops: Round-Trip Examples}

  \begin{itemize}

   \item Poisson solve
    \begin{itemize}
    \item Round-trip, input: Real array (2D, $N_x\times{}N_y$)
    \item Output: find $f$ such that $\nabla^2{f} = \phi$
    \item Mid op: $x_{i_x, i_y} \rightarrow \frac{-x_{i_x, i_y} }{ k_x^2 + k_y^2}$
    \item Maybe a constant scale as well
    \item Use case: molecular dynamics
    \end{itemize}
  \item Phase-shift dealiased convolution for Navier--Stokes
    \begin{itemize}
    \item Input: Three Hermitian 3D arrays, cubic
    \item Read op:
      \begin{itemize}
      \item Read-op:
        $u
          \rightarrow \(u, \omega = \nabla \times u\)
          \rightarrow \(u, \omega, \tilde{u}, \tilde{\omega}\)
          $
        \item $\tilde{u}$ is $u$ with a $\(1/2, 1/2, 1/2\)$ phase shift.
      \end{itemize}
    \item Mid-op: two copies of 
      \begin{dmath}
        \(f_0, f_1, f_2, f_3, f_4, f_5\)
        \rightarrow
        \(
        f_4 f_2 - f_5 f_1,
        f_5 f_1 - f_3 f_2,
        f_3 f_1 - f_4 f_0
        \)
      \end{dmath}
    \item write-op: combine-and-zero
      \begin{itemize}
      \item $\(f_0, f_1, f_2, f_3, f_4, f_5\)
        \rightarrow
        \(f_0 + f_1, f_2 + f_3, f_4 + f_5 \)$
      \item All values with $\left|k\right| > N$ set to zero.
      \end{itemize}
    \item Use-case: GESTS (they also add a passive scalar field).
    \end{itemize}
  \end{itemize}
  
\end{frame}

\begin{frame}
  \frametitle{Spectral Ops: convolution examples}

  These examples need zero-padding to dealias convolutions.
  
  \begin{itemize}

  \item Source term for vorticity Navier--Stokes 2D
    \begin{itemize}
      \item Input: 2D Hermitian array
      \item Read-op: $\omega \rightarrow
        \(
        ik_x\omega,
        \frac{ik_x}{k_x^2 + k_y^2}\omega,
        ik_y\omega,
        \frac{ik_y}{k_x^2 + k_y^2}\omega
        \)$
      \item mid-op: $\(f_0, f_1, f_2, f_3\) \rightarrow \( f_3 f_0 - f_2 f_0 \)$
    \end{itemize}
  \item Convolution for ML
    \begin{itemize}
    \item Mid-op: $\(f,g\)\rightarrow fg$
    \item $f$ is a constant filter: only transform once, keep data for later mid-ops.
    \end{itemize}
  \item Dealiased autocorrelation
    \begin{itemize}
    \item mid-op: input multiplied by its complex conjugate: $f \rightarrow \bar{f}f$
    \end{itemize}
  \end{itemize}
  
\end{frame}


\begin{frame}
  \frametitle{Spectral Ops: ops}

  \medskip
  Operations are:
  \begin{itemize}
  \item local: depend on index and batch number
    \begin{itemize}
    \item Option: allow for a user-supplied buffer
    \item Option: allow access to shared memory
      \end{itemize}
  \item can have many inputs and outputs
    \begin{itemize}
    \item Option: ops may only touch a subset of inputs/outputs
    \item Option: inputs/outputs can have different types
    \item Option: inputs/outputs can have different lengths
    \item Option: some inputs may be constant over executions
    \end{itemize}
  \item Have user-supplied constants (RTC'd in)
  \item Multiplicative mid-ops may require dealiasing (eg conv)
  \end{itemize}

  \bigskip

  There are lots of possible operations, and combinations thereof.


\end{frame}

\begin{frame}
  \frametitle{Sparsity}

  \begin{center}
    Sparsity is about \emph{data properties}.
  \end{center}

  
  Given the brick decomposition in the multi-GPU section, we can mark
  bricks as containing only zero data.

  \medskip

  \begin{itemize}
  \item Bricks can be marked as sparse, ie all zero.
  \item Or we can add compression!  Perhaps lossy!
  \item Separate sparsity for inputs and output.
  \item Brick-based sparsity design
    \begin{itemize}
    \item spectral data seem to have coarser sparsity patterns
    \item csr or coordinate list doesn't seem relevant
    \end{itemize}
  \end{itemize}
      
\end{frame}


\begin{frame}
  \frametitle{Spectral ops API proposal}

  Callbacks are absurdly slow in ROCm.
  \begin{itemize}
  \item NVIDIA has moved to JIT to improve callback performance (\href{https://www.nvidia.com/en-us/on-demand/session/gtcfall21-a31155/?playlistId=playList-ead11304-9931-4e91-9d5a-fb0e1ef27014}{link})
  \item We ca make use of RTC to do this in rocFFT.
  \end{itemize}

  \bigskip
  
  Spectral ops API proposal:
  \begin{itemize}
  \item RTC-based general API
  \item rocFFT generates a function signature
  \item The user provides the body of the function
  \item Similar complexity to callbacks, but better ROCm perf
  \end{itemize}
  
\end{frame}

  \item \texttt{vkFFT}: Convolution matrix, symmetry, fused kernels

  \item \texttt{FFTW++}: pointer-based spectral ops for convolutions
  \item \texttt{safari}: binary convolution with normalized spec op for ML
  \end{itemize}

  \medskip

  Multi-GPU:
  \begin{itemize}
  \item \texttt{cuFFTXt}: single-node, only slab decomposition
  \item \texttt{cuFFTMp}: brick decomposition
  \item \texttt{heFFTe}: brick decomposition
  \item \texttt{FFTW++}: pencil decomposition
  \item \texttt{SpFFT}: also sparsity
  \end{itemize}

\begin{frame}[fragile]
  \frametitle{Spectral op example: 2D Navier--Stokes vorticity formulation}

  \begin{itemize}
  \item Create a spectral op \lstinline{readop} with RTC string:
    \begin{lstlisting}
if(posx == 0 && posy == 0) {
  out0 = out1 = out2 = out3 = 0.0;
  return;
}
const double Lx = 2.0, Ly = 2.0; // Physical constants
const double kx = 2 * pi * (posx < Nx/2 ? posx : Nx - posx) / Lx;
const double ky = 2 * pi * posy / Ly;
const double denom = 1.0 / (kx * kx + ky * ky)
const hipComplexDouble I(0,1);
out0 = in0 * I * ky * denom;
out1 = in0 * I * kx;
out2 = in0 * I * kx * denom;
out3 = in0 * I * ky;
    \end{lstlisting}
  \item Add \lstinline{readop} to the \lstinline{description}.
  \end{itemize}

\end{frame}

  \begin{itemize}
  \item Specify that readop takes input field 0 and output fields $0,1,2,3$.
  \item Create a midop which takes fields  $0,1,2,3$ and produces field 0.
  \item Midop rtc string is \lstinline{out0 = in0 * in1 - in2 * in3}.
  \item Type is \texttt{rocfft_transform_type_real_inverse_roundtrip}
  \item Specify convolution order 2, type is centered.
  \item \texttt{rocFFT} creates 4 internal fields, and we execute with the normal GPU bufs.
  \end{itemize}
  
\end{frame}

\begin{frame}[fragile]
  \frametitle{Spectral op example: per-batch 1D complex-to-real phase
    shift-and-scale}
  \begin{itemize}
  \item Readop with string
    \begin{lstlisting}
      out0 = in1 * s(posb0) * exp(2 * pi * i * f(posb0);
    \end{lstlisting}
  \item \lstinline{posb0} is the batch index.
  \item \texttt{rocFFT} creates the function signature
    \begin{lstlisting}
      __device__ void(double &out0, const double in0, size_t posx, size_t posb0, void* args);
    \end{lstlisting}
  \item Transform type is \texttt{rocfft_transform_type_real_inverse}
  \item Allocate a 1D batch of 1D (Hermitian-symmetric) complex arrays.
  \item Execute with the GPU buffer pointers.
  \end{itemize}
  
\end{frame}

\begin{frame}
  \frametitle{Special cases}

  It may be worth having special cases for certain functions, eg
  convolution, Poisson solve.

  \medskip

  \begin{itemize}
  \item Binary convolution can also be possibly optimized (eg
    Winograd, matrix cores, etc).
  \item Easier for users to get at common use cases.
  \item Heavier API: more to test, more to document, more to write.
  \end{itemize}
  
\end{frame}

\begin{frame}
  \frametitle{Optional Additions}

  Besides the basic API design shown above, we have more optional
  functionality that we can add:

  \medskip
  
  \begin{itemize}
  \item Multi-value spectral ops can have a field-dependency list.
  \item Multi-GPU transforms can have lossy compression for communication.
  \item Convolution outputs can have different lengths than inputs.
  \item Cooperation with CPU and FPGA groups at AMD.
  \end{itemize}
  
  
\end{frame}
