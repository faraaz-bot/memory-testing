\section{Use cases}


\subsection{Convolution/correlation}

We can have an arbitrary number of inputs.  Each input can have its
own format (length, stride, precision).  Typically, inputs will have
the same type (ie real vs complex), but it would be perfectly
reasonable to convolve real data with complex data, or complex data
with Hermitian-symmetric complex data.  Real and Hermitian-symmetric
complex wouldn't really make sense, as they are on opposite sides of
the Fourier transform.  In general, we expect that all inputs and
outputs be in the same space, ie either all in the time/space domain
or all in the frequency domain.

The convolution of two inputs $\{f_n\}$ and $\{g_n\}$ is denoted
$f\ast{}g$ and is given by
\begin{dmath}
  f\ast{}g_\ell
  = \sum_m f_m g_{\ell-m}
  = \sum_{m_0}\sum_{m_1}f_{m_0} g_{m_1} \delta_{\ell, m_0 + m_1}
\end{dmath}
where
\begin{dmath}
  \delta_{a,b} = \begin{cases}
  1  & a=b  \\
  0 & a \neq b
\end{cases}
\end{dmath}
is the Kronecker delta.  This can be extended from a binary convolution
to a general $n$-ary conovlution as
\begin{dmath}
  \label{nary}
  \ast{}\(f_0, \dots, f_{n-1} \)_\ell
  = \sum_{m_0, \dots, m_{n-1}} f_{m_0} \dots f_{m_{n-1}}  \delta_{\ell, \sum m_i} 
\end{dmath}

Note that the bounds on equation~\eqref{nary} are not given.  For
$\{f_n\}_{n=0}^{N-1}$, $\{g_n\}_{n=0}^{M-1}$, \href{https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.fftconvolve.html#scipy.signal.fftconvolve}{python}
allows for outputs of length
\begin{itemize}
\item \texttt{full}: $\max(M,N)$
\item \texttt{valid}: $M+N-1$
\item \texttt{same}:  $\max(M, N) - \min(M, N) + 1$.
\end{itemize}

For $\{f_n\}_{n=-N+1}^{N-1}$, $\{g_n\}_{n=-M+1}^{M-1}$, we have a
centered convolution (which is typical for Hermitian-symmetric data
involved in pseudospectral simulations of, eg, Navier--Stokes flow and
MHD), the output typically has \texttt{full} output.

In terms of internal implementation, centered Hermitian convolutions
needs a different algorithm depending on the order of the operator.
In particular, while centered $n$-ary convolutions can be efficienctly
computed via a series of binary convolutions without extra padding for
dealiasing, this is not the case for centered convolutions, where
\texttt{full} output will result in the convolution being
non-associative.

\subsection{Shift}

The shift function is a nice Fourier transform trick which allows one
to move perform an affine transform in index space by multiplying by
roots of unity.  Multiplying the input via
\begin{dmath}
  u_{n} \leftarrow \omega^{\alpha + \beta n} u_{n}
\end{dmath}
maps the output to
\begin{dmath}
  U_{k} \leftarrow U_{\alpha + \beta k}
\end{dmath}

\subsection{Differentiation}

The Fourier transform maps differentiation to component-wise
multiplication.  This is because
\begin{dmath}
  \mathcal{F}\left[\partial_x u\right]
  = \int  \partial_x e^{ikx} u(x) dx 
  = ik \int  e^{ikx} u(x)
  = ik U(k).
\end{dmath}
The operator is
\begin{dmath}
  \hat{f} \leftarrow i k \hat{f}
\end{dmath}
where $k$ depends on the index and some constant factor.


\subsection{Poisson solver}

Solving the Poisson equation is a round-trip operation.  The Poisson
equation is
\begin{dmath}
  \label{poisson}
  \nabla^2 \phi = f
\end{dmath}
By taking the transform of equation~\eqref{poisson}, we get
\begin{dmath}
  (ik)^2 \hat{\phi} = \hat{f}
\end{dmath}
so we can solve for $\hat{\phi} = -\hat{f}/k^2$ and then
get $\phi$ by inverting the transform.  The operation is
\begin{dmath}
\hat\phi_{k} = \begin{cases}
  -\hat{f}_k/{k^2}  & k\neq 0  \\
  0 & k=0
  \end{cases}
\end{dmath}
The $0$-mode is solved by setting appropriate boundary conditions.  

\subsection{Filter}

Filters are round-trip operations which is linearized by the FFT.  The
low-pass filter with cutoff $k_c$ 
\begin{dmath}
\hat{f}_{k} = \begin{cases}
  \hat{f}  & k < k_c  \\
  0  & k \geq k
  \end{cases}
\end{dmath}
and similar for a low-pass filter.  Note that this can be optimized by
skipping zero-data on the inverse transform.  Other filter choices may
be smoother, or have some more complicated behaviour.

\subsection{Hamming window}

Since the FFT works on periodic signals, non-periodic signals are
often windowed in order to improve results, and the Hamming window is
a popular choice.  This can be used in round-trip operations, or as
part of a normal transform.  The operation is
\begin{dmath}
  f_n \leftarrow w(x_n) f_n
\end{dmath}
where $x_n$ depends on the index $n$ and some constant values.

\subsection{applications}

Other applications inlclude
\begin{itemize}
\item upsampling, which seems to be a transform, extension with zero-padding, and an inverse transform of an extended length.
\item non-uniform FFTs (see \url{https://finufft.readthedocs.io/})
\item image compression, which seems to be a high-amplitude filter
\item cross-correlation, which involved finding the index of the
  maximum of the output of a correlation
\end{itemize}


\section{Other libraries}

Other libraries also offer varios spectral operations as part of a larger
FFT package.

\subsection{Python}

Python has a convolution operator which computes non-centered
convolution on two inputs and one output.  Mismatched sizes are
handled (though not in generality), and the output can have different
sizes (\texttt{full}, \texttt{valid}, \texttt{same}) and
\href{https://docs.scipy.org/doc/scipy/reference/generated/scipy.signal.convolve2d.html}{scipy.signal.convolve2d}
offers similarly-named options for the boundary.

Python implements a
\href{https://numpy.org/doc/stable/reference/generated/numpy.fft.fftshift.html}{shift}
operator which allows one to shift the Fourier origin to the middle of
the array.

\subsection{vkFFT}

vkFFT offers conovlution operators, though no examples are given and
it's hard to tell what the interface is in the 40 000 lines which make
up the single file of the header-only library.  From discussion with
and talks by the author, vkFFT makes use of shuffled Cooley-Tukey
transforms and probably keeps at least the last stage of the FFT
in-flight (ie avoids a global memory round-trip) to achieve a
$\approx30\%$ speedup as compared with \texttt{cuFFT}.

\subsection{cuFFTDx}

\href{https://docs.nvidia.com/cuda/cufftdx/index.html}{\texttt{cuFFTDx}}
allows the user to embed FFT kernels into their own cuda code.  This
allows for user-defined spectral operations which are quite general.
However, size limitations are quite restrictive, with double-precision
transforms being limited to length 16384 (see
\href{https://docs.nvidia.com/cuda/cufftdx/requirements_func.html#supported-functionality}{supported-functionality}
for details.)  It appears that multi-dimensional FFTs are not
supported.  The interface seems quite complicated, but does offer a
very flexible framework for the supported transforms.

\subsection{Spiral/FFTX}

\href{http://www.spiral.net/software/fftx.html}{Spiral/FFTX} is a
different beast entirely; this is essentially a code generator which
can generate very general spectral operations.  They have CPU, CUDA,
and HIP back-ends.  The interface is quite complicated; one writes a
specification in \texttt{C++} which is turned into a program and
compiled.  The user interface is based on tensor notation (cf: Van
Loan's FFT book).  While quite general, the user interface is very
difficult to use.  The authors are unaware of implicitly dealiased
convolution routines.

\subsection{FFTW++}

\href{https://github.com/dealias/fftwpp}{FFTW++} is a wrapper for FFTW
which also includes convolution routines.  Implicitly dealised
convolutions are implemented, which offer better performance than
conventional routines.  Centered and non-centered conovlutions are
handled, including ternary centered convolutions.  The number of
inputs and outputs is arbitrary, but they must all have the same size.
The pointwiser operator is given via a function pointer.  An MPI
interface is provided.

\subsection{FastFFT}
\href{https://github.com/StochasticAnalytics/FastFFT/}{FastFFT} is
another library which offers some interesting 2D spectral operations.
They seem to offer a cross-correlation peak locator which skips a vram
round-trip.  Works on cuda.  Worth looking into a bit more.

\subsection{cutensor}
\href{https://docs.nvidia.com/cuda/cutensor/getting_started.html}{cutensor}
offers and API for specifying array dimensions which may be useful for
the round-trip API in rocFFT.

\section{Spectral operator API proposal}

There are two basic cases:
\begin{enumerate}
\item Part-of-transform
\item Round-trip
\end{enumerate}

\subsection{Indexing function}

The pointwise operation may depend on the logical index, which isn't
necessarily going to be the same as the array index.  For example, 1D
transforms which use multiple kernels will have effectively transposed
the data; the map from array index to logical index depends on the FFT
plan.  For index-dependant functions, we will need the index map in
order to correctly apply the pointwise function.

This can also just be an optimisation.

\subsection{Part-of-transform}

For differentiation, shift, result scaling, and amplitude filters.

The functionality here is similar to use cases for callback API.
However, the callback functionality doesn't know about the
array-index-to-logical-index map.  Also, the performance of callbacks
have been very problematic on the GPU, so moving to another API where
we can RTC user-specified functions into the FFT kernel will allow for
significantly better performance.  As with the callback API, we can specify
a load and a store function.  The functions have signature
\begin{lstlisting}
Tval f(Tval u, size_t idx_x, size_t idx_y, size_t idx_z)
\end{lstlisting}
That is, they take exactly one value (real or complex) and a
multi-index, and return exactly one value of the same type.

For example, a Poisson solve is provided by
\begin{lstlisting}
Tval f(Tval u, size_t idx_x, size_t idx_y, size_t idx_z)
{
  const double k0 = 2.0; // User-specified
  const double k2 = k0 * k0
         * (idx_x * idx_x +  idx_y * idx_y +  idx_z * idx_z);
  if(k2 == 0)
     return u;
  return u / k2;
}
\end{lstlisting}

A low-pass filter is provided by
\begin{lstlisting}
Tval f(Tval u, size_t idx_x, size_t idx_y, size_t idx_z)
{
  const double k0 = 2.0; // User-specified
  const double k2 = k0 * k0
         * (idx_x * idx_x +  idx_y * idx_y +  idx_z * idx_z);
  if(k2 > cutoff)
     return 0;
  return u;
}
\end{lstlisting}

A shift operator is provided by
\begin{lstlisting}
Tval f(Tval u, size_t idx_x, size_t idx_y, size_t idx_z)
{
  const Tval omega = exp(2 * pi / N); // User-specified
  return u * pow(omega, a + b * idx_x);
}
\end{lstlisting}

We will have to provide a method of getting the complex type from the
real type and vice-versa.

\subsection{Round-trip}

Convolution, Poisson solve, high/low-pass filters, 

Can be combined with pre/post functions, eg: windowed transform.

We add the information to the \texttt{rocfft_plan_description}.  We
need to specify the lengths and strides separately for each input
buffer.  We can have an arbitrary number of inputs and outputs.  Outputs
can be mixed real/complex or complex/Hermitian-complex.

We need to specify the order of the operation: Poisson solves are
order-1, binary convolutions are order-2, ternary convolutions are
order-3, etc.

We need to specify the pointwise operator.  This has to match the
order of the operation (eg: $-u/k^2$ is order-1, $u\odot v$ is
order-2, etc).  If the operator has higher order than what is
specified, then incorrect results will be returned.
