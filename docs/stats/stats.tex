\begin{frame}
    \frametitle{Problem}
    
    Common strategies:
    \begin{itemize}
    \item Run 10 times, take the minimum
      \begin{itemize}
      \item Idea: show the ``power'' of the device.
      \item \dots{} but we have no confidence that we got the minimum.
      \end{itemize}
    \item Plot the data
      \begin{itemize}
      \item Idea: if the lines are on top of each other, call it a wash.
      \item \dots{} that's a lot of graphs to look at.
      \item \dots{} this doesn't automate well.
      \end{itemize}
    \item Cut-off based on effect size
      \begin{itemize}
      \item Idea: if the difference is $<5\%$, call it a wash.
      \item \dots{} what if we have two regressions of $3\%$?
      \end{itemize}
    \end{itemize}
    
    \medskip
    \begin{center}
      How can we build confidence in our performance tests?
    \end{center}
    
\end{frame}

\begin{frame}
    \frametitle{Actual proposed solution}

    Problem:
    \begin{itemize}
    \item Performance tests are surprisingly noisy.
    \item The noise isn't the same over tests
    \end{itemize}
        
    \bigskip

    Solution:
    \begin{itemize}
    \item Choose an experimental design that eliminates bias.
    \item Use statistical tests to handle noise.
    \end{itemize}

\end{frame}

\begin{frame}
  \frametitle{Experimental design}

  
    \begin{itemize}    
    \item Noise (aka jitter) is a fact of life.
      \medskip
    \item We can't do statistical tests if the noise isn't identically
      distributed.
      \medskip
    \item Some runs get more noise - why?  What can we do?
    \end{itemize}
  
\end{frame}

\begin{frame}
  \frametitle{Sequential experimental design}

  \begin{center}
    Hypothesis:
  \end{center}

  \bigskip

  The device is intermittently interrupted.

  \bigskip

  This interruption is time-correlated.

  \bigskip
  
  Therefore, the noise is time-correlated.

  \bigskip

  To decorrelate noise and test case, we must de-correlate test case
  with time.
    
  
\end{frame}

    \end{center}

\begin{frame}
    \frametitle{Randomized Design}

    Alternating test cases won't eliminate alternating noise.

    \bigskip
    
    \begin{itemize}
    \item If we're alternating we may as well randomize.
    \item Random case choice maximally reduces correlation.
    \item For $N$ samples, either:
      \begin{itemize}
      \item randomly pick a case until we have at least $N$ samples per case,
      \item or take the sequential case and shuffle the order.
      \end{itemize}
    \end{itemize}

\begin{frame}
    \frametitle{Measurement of Central Tendency}


    There are two basic measures of central tendency:

    \begin{itemize}
    \item Mean
    \item Median
    \end{itemize}

    Our data can be quite skewed and has outliers \pause{} - the mean
    can be quite unstable in this context.
   
    \begin{center}
      \includegraphics[width=0.5\textwidth]{img/mean_median_skew_meme.jpg}
    \end{center}
    \pause{}
    
    The median is also stable under monotonic transforms, eg:
    \begin{itemize}
    \item time $\rightarrow$ gflops
    \item time $\rightarrow$ bandwidth
    \end{itemize}
    
\end{frame}

\begin{frame}
    \frametitle{Uncertainty quantification}

    Whichever measure we choose, we need to quantify the uncertainty.

    \bigskip

    The mean is associated with standard deviation
    \begin{itemize}
    \item Assumes a normal distribution
    \item The mean minus the standard deviation is often negative
      \begin{itemize}
      \item Negative values are difficult to plot on log-log plots.
      \end{itemize}
    \end{itemize}

    %\pause
    
    \bigskip
    
    Alternative: bootstrap resampling.
    \begin{itemize}
    \item Given $N$ data points, sample, with replacement $N$ value.
    \item Compute a new statistic (ie mean or median).
    \item Do this a lot (like 2000 times).
    \item The range of the middle $90\%$ values gives the $90\%$
      confidence interval.
    \item Slightly expensive but incredibly robust.
    \end{itemize}
    

\end{frame}

\begin{frame}
    \frametitle{Statistical tests}

    We have a variety of tests to look choose from.

    \bigskip

    Since we are graphing median execution times, Mood's median test
    is a natural choice.

    \bigskip

    \begin{itemize}
    \item Non-parametric
      \begin{itemize}
      \item ie, it doesn't rely on a particular distribution (eg Bell
        curve).
      \item Our data is clearly doesn't follow a nice distribution.
      \end{itemize}
    \item Tests whether the difference in the medians between two
      samples is due to noise.
    \end{itemize}

\end{frame}
    

\begin{frame}
  \frametitle{Statistical tests}

  Other interesting statistical tests:
  \bigskip
  \begin{itemize}
  \item Mann-Whitney U test
    \begin{itemize}
    \item Tests whether a random time from one case tends to be larger
      than a random time from the other case.
    \item Also non-parametric
    \end{itemize}
  \item Student's t-test
    \begin{itemize}
    \item Tests whether the difference means of the two cases are due
      to noise or not.
    \item Assumptions are made about the underlying distribution.
    \item By the central limit theorem, we do get closer to normality
      with more samples!
    \item Rule of thumb seems to be that we need $\geq{}100$ samples.
    \end{itemize}
  \end{itemize}

 
\end{frame}


\begin{frame}
  \frametitle{Multiple-Hypothesis tests}

  In particular, we do multiple-hypothesis testing.

  \bigskip

  For each test, we get a $p$ value.
  \begin{itemize}
  \item Sometimes, the noise correlates with the case.
  \item So, sometimes, our test gives us a significant $p$ value.
  \item If we do enough tests, something will end up significant.
  \end{itemize}

  \bigskip

  These false-positives are known as type-1 errors.

  \bigskip

  We do not want to $p$-hack ourselves.

\end{frame}
  
\begin{frame}
  \frametitle{Multiple-Hypothesis tests}

  \begin{center}
    How to avoid getting $p$-hacked:
  \end{center}

  \bigskip

  Bonferroni correction:
  \begin{itemize}
  \item For $N$ tests, use $p/N$ instead of $p$.
  \item We then expect a stable false-positive rate close to $p$.
  \item Smaller $N$ is better - try and find an independent yet
    representative test suite.
  \end{itemize}

  \bigskip
  Empirical distribution testing
  \begin{itemize}
  \item We can use the observed distributions as a baseline.
  \item More complicated; future work if we need it.
  \end{itemize}
  
\end{frame}

\begin{frame}
  \frametitle{Performance Tuning}

  Statistical tests give us a $p$-value:
  \begin{itemize}
  \item The probability that the results are due to random noise.
  \end{itemize}

  \bigskip

  We talk about algorithm performance in a similar fashion:
  \begin{itemize}
  \item ``Method A usually gives better performance.'
  \end{itemize}

  \bigskip

  We can use this prior knowledge in conjunction with statistical tests:
  \begin{itemize}
  \item Our prior knowledge is that A is better than B with probability $p_0$.
  \item A statistical test gives us a new $p$
  \item Combine $p_0$ and $p$ to give us a new probability $p'$.
  \end{itemize}

  \bigskip
  Some sort of Bayesian algorithm prediction.
  
\end{frame}
